# 反编译方法、覆盖与可信度

## 使用的证据

归档清单和 SHA256；ELF／Go 构建元数据；Go pclntab 的函数边界；Go 类型反射元数据；内嵌前端文件名；只读 SQLite 表结构与计数；包内说明／默认 SQL；选定函数的 Ghidra 伪代码。未执行被分析主程序和附属工具。

## 地址纠正

样本的 Go 1.27 pcHeader 中 textStart 为零。使用零值或仅以函数偏移定位会造成错误；本次用模块／ELF 对齐，实际文本基址为 **0x11000**。早期仅偏移定位的伪代码已判无效，不能作为功能证据或与有效结果混合计数。

GoReSym 1.7.1 在本样本上未正确识别对应 moduledata，Types 为空且地址结果不可靠。类型恢复改用与 Go 1.27 运行时布局核对的解析方式，并对字段偏移、类型和 JSON 标签检查。

## 覆盖统计

真实函数条目是 **31,903**；包含内联名称的字符串表有更多名字，不能把后者当作真实函数数量。

选定恢复首批 52 个函数、追加 119 个目标，二者重叠 3 个，合计 **168 个唯一函数**。恢复 **37 个命名结构体**。这些只是选定覆盖，不是完整应用源码，也不能据此计算所有功能已验证的比例。

公开函数地址索引来自纠正后的真实函数边界。恢复覆盖清单不包含函数体。公开类型摘要仅保留名称、大小和字段数量，不重新分发完整通信结构或执行实现。

## 证据等级与不确定性

1. 文件／字段／函数名：证明对象存在，不证明真实运行成功。
2. 选定伪代码：可证明部分控制或调用关系，但 Go ABI、寄存器和类型推断会丢失信息。
3. 包内说明与 SQL：证明随包材料的主张或配置，不证明实际环境已经采用。
4. 动态效果：本次没有执行，全部保留为未验证。

尚未完整验证：全部请求 schema、传输／协议兼容、鉴权与审批覆盖、并发与取消、失败重试、重启恢复、真实连通性、附属工具架构兼容、知识有效性、漏洞发现率和成本收益。

## 复核方式

先用 provenance.json 的指纹确定同一样本，再核对相对路径统计、只读数据库计数、嵌入页面和函数名。名称索引要与实际函数边界对应；原始提取路由字符串含拼接噪声，未作为完整可靠 OpenAPI 发布。

本仓库仅公开派生分析，不提供被分析样本、目标数据、可执行材料、敏感配置或反编译执行代码。读者不能从本报告取得完整原始源码。
